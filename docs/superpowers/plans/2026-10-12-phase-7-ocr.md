# Phase 7 (OCR) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make scanned pages searchable, selectable and editable by adding an invisible text layer recognised with Tesseract.js, entirely in the browser.

**Architecture:** Tesseract.js (named in spec §3.1) runs in its own worker. Everything it needs is self-hosted under `/ocr/` (its worker script, the WASM core, English `eng.traineddata`), copied there at build time. The UI renders a page to a bitmap at 300 dpi with the engine, hands it to Tesseract, and gets words with bounding boxes. An `ocr.addLayer { page, words: { text, bbox }[] }` op draws them as invisible text (render mode 3) in a bundled font, scaled so each word's box matches, in a tagged section. Search, selection and Phase 5 editing then work on it (Phase 5 refuses to edit invisible text in place; an OCR'd page offers "make this text editable" later, out of scope here).

## Constraints and decisions
- **Tesseract.js defaults violate the spec** and are overridden: `workerPath`, `corePath`, `langPath` point at our origin (default: a CDN), and `cacheMethod: 'none'` (default: caches language data in IndexedDB, which §2 forbids).
- **Lazy loading vs "no requests after load"**: the spec loads Tesseract lazily (§3.1), which conflicts with success criterion 3 read literally. Decision: the OCR assets (~5 MB) are fetched from our own origin only when the user starts OCR; they carry no document data. The privacy e2e keeps asserting zero requests after load for all other flows, and for the OCR flow asserts that every request is a same-origin GET under `/ocr/`. Flagged to the owner.
- New dependency: `tesseract.js` (named in the spec). Its transitive `idb-keyval` is unused with `cacheMethod: 'none'` (asserted by the privacy test: IndexedDB stays empty).

## Tasks
1. Self-host assets: a small Vite plugin / build step copying `tesseract.js/dist/worker.min.js`, `tesseract.js-core` WASM files and `eng.traineddata` (from the tessdata_fast repo, Apache-2.0) into `public/ocr/`; license notes.
2. Engine: `ocr.addLayer` op + tests (structured text finds the words at the given boxes; text is invisible in rendering; search hits; undo).
3. UI: "Recognize text (OCR)" for the current page / all pages without text, progress, cancel; detection of image-only pages; e2e with a scanned-page fixture (rendered text image without a text layer).
4. Privacy e2e for the OCR flow; README; review; PR.

# Phase 8 (PDF → Word) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Export the open PDF as a .docx with its text as paragraphs (size, bold, italic, alignment), its images, and simple tables where they can be detected. Fidelity is best-effort and the UI says so. DOCX → PDF stays out of scope (spec §6, §11).

**Architecture:** The engine turns each page into a small document model from MuPDF's structured text (`preserve-images`): blocks → paragraphs (lines joined; hyphenated line ends rejoined; a new paragraph on a large vertical gap or indentation change), runs with font size and bold/italic (from font names/flags), paragraph alignment (left/center/right by comparing line edges to the block), images as PNG with their displayed size, and tables: a group of ≥2 consecutive rows whose cells (gap-separated runs, as in Phase 2's `textRuns`) line up on ≥2 shared column edges becomes a grid. The UI lazily loads `docx` (named in spec §3.1, self-hosted via the bundle) and builds the file from the model: one section per page size, page breaks between pages, images inline at their size.

## Model

```ts
type DocRun = { text: string; size: number; bold: boolean; italic: boolean; color: Color };
type DocBlock =
  | { kind: 'paragraph'; align: 'left' | 'center' | 'right'; runs: DocRun[]; spaceBefore: number }
  | { kind: 'image'; png: Uint8Array; width: number; height: number }       // points
  | { kind: 'table'; rows: DocRun[][][] };                                     // row -> cell -> runs
type DocPage = { width: number; height: number; blocks: DocBlock[] };
```

## Tasks
1. Engine `documentModel(pages?)` + tests on simple.pdf (paragraphs), invoice.pdf (a 4-column table with the line items; header bold), a centered-title fixture, an image fixture; hyphenation rejoin.
2. `docx` dependency (spec-named), lazy import; `buildDocx(model): Promise<Blob>` + unit test that unzips the result (JSZip is a docx dependency) and finds the expected text and a table in `word/document.xml`.
3. UI: "Export to Word (.docx)" in the download menu with a short best-effort note; e2e downloads and inspects the docx.
4. Privacy e2e (export makes no requests beyond the lazy same-origin chunk), README, review, PR.

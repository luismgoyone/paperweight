# Click-to-fill for Flat Forms Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On a PDF with no form fields (a "flat" form: printed, scanned, or re-saved from Word), Form fill highlights the empty boxes and checkboxes it detects; clicking a box opens a text box fitted to it, and clicking a checkbox toggles an "X".

**Architecture:** Detection works on the rendered page, not the drawing commands. Word-made forms draw borders as thousands of hairline rectangles, and blank cells are never drawn at all. The engine renders the page in grey at 2× (annotations off) and flood-fills the near-white pixels. Each enclosed white region that doesn't touch the page edge, is at least 6 pt each way, and fills ≥ 60% of its bounding box is a candidate. Small squarish candidates (≤ 20 pt, aspect 0.6–1.6) are checkboxes; the rest are text slots. The UI drops candidates that overlap the PDF's own text (label cells), ignoring text the user added, so a filled box stays clickable. Filling produces ordinary `text.add` / `text.delete` ops, so undo, save, flatten and Word export work unchanged.

**Tech Stack:** MuPDF.js (render to `DeviceGray` pixmap), TypeScript, React, Zustand, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-12-pdf-editor-design.md` (§2 privacy, §5 UI, §6 Phase 3 forms). This adds a feature the spec doesn't list; it changes no spec decision.

## Global Constraints

- Everything runs in the browser; no network requests, nothing stored (spec §2). Detection is local pixel work in the engine worker.
- `engine/` must not import ui/editor/react; `ui/` must not import mupdf or `engine/*`; shared types live in `src/shared/types.ts`.
- No new dependencies.
- PDFs with real AcroForm fields keep the existing Form fill behaviour unchanged.
- Fixtures are synthetic (generated by `scripts/make-fixtures.mjs`); no real forms or personal data in the repo.

## Review Focus

1. A box the user already typed into must stay clickable (detection sees the user's text as ink). Pinned in Task 2 (`usableSlots` ignores runs inside added text objects).
2. Grey label cells and white cells with printed labels must not become slots. Pinned in Task 1 (grey cell) and Task 2 (printed label).
3. The white page margin and the area around the form must never be a slot (it touches the page edge). Pinned in Task 1.
4. Clicking a checkbox twice must remove the X, not add a second one. Pinned in Task 4 e2e.
5. Pages with no detectable boxes must say so instead of silently doing nothing. Pinned in Task 4 e2e (banner text on simple.pdf).
